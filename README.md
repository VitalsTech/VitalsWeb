# Vitals — интерфейсы пациента и врача

Веб-интерфейс цифровой медицинской экосистемы Vitals: отдельные разделы для пациента и врача,
выбор роли на экране входа. Свёрстан по макету в Figma (React + TypeScript + Vite + Tailwind
CSS v4 + React Router) и подключён к API Gateway Vitals по контракту (`contract.txt`, OpenAPI).

## Стек

- React 19 + TypeScript
- Vite 6
- Tailwind CSS v4 (`@tailwindcss/vite`)
- React Router v7
- Тема: light/dark через CSS-переменные и класс `.dark` на `<html>`, переключатель в сайдбаре

## Роли и вход

- Единый экран `/auth` (`src/pages/Auth.tsx`) с переключателем **«Я пациент» / «Я врач»** —
  определяет, какой профиль используется при входе/регистрации и куда попадёт пользователь после
  успешной аутентификации (`/patient` или `/doctor`).
- Роль и id профиля (`patientId`/`doctorId`) хранятся в `localStorage` (`src/api/tokenStore.ts`) и
  восстанавливаются при обновлении страницы; `AuthProvider` (`src/auth/AuthProvider.tsx`)
  подгружает нужный профиль через `/users/profiles`.
- `PatientLayout`/`DoctorLayout` (`src/layouts/*`) содержат ролевые guard'ы: аккаунт без
  соответствующего профиля перенаправляется в свою область (пациент → `/patient`, врач →
  `/doctor`), общий сайдбар (`src/components/Sidebar.tsx`) переиспользуется для обеих ролей через
  пропсы `roleLabel`/`navItems`.

## Backend / API

- Контракт: OpenAPI-спецификация API Gateway (Auth, Users, Doctors, Triage, Consultations,
  MedicalRecords, Prescriptions, Notifications, Payments…).
- Все обращения к API описаны в `src/api/*`: `http.ts` — общий fetch-клиент с авто-обновлением
  токена (refresh) и обработкой ошибок, остальные файлы — по одному на тег контракта.
- Аутентификация — JWT Bearer. Токены, `publicId`, `patientId`/`doctorId` и `role` хранятся в
  `localStorage` (`src/api/tokenStore.ts`); id профиля при необходимости восстанавливаются из
  payload access-токена, так как ответы `/auth/login|register|refresh` не документированы
  контрактом (только `200 OK`), а сам JWT самодостаточен.
- Контракт не документирует тела ответов для GET-эндпоинтов — DTO в `src/api/*.ts` намеренно
  «мягкие» (опциональные поля + `[key: string]: unknown`), а компоненты страниц отрисовывают
  доступные поля с осмысленными заглушками, если чего-то нет.
- Несколько экранов используют `medical-records` events (`AppendEventRequestDto`) как универсальный
  журнал для сценариев, не имеющих отдельного эндпоинта в контракте (отметка самочувствия, вызов
  врача на дом, обращение в поддержку, карточки документов, направления и правки диагнозов от
  врача).
- Редактирование личных данных профиля (ФИО, дата рождения, телефон) недоступно — в контракте нет
  соответствующего эндпоинта; доступна только смена пароля (`/auth/change-password`).

### Ограничения контракта для врача

Контракт не содержит эндпоинтов «список пациентов врача» или «список активных консультаций
врача», поэтому для интерфейса врача добавлена облегчённая клиентская замена:

- `src/pages/doctor/contacts.ts` — локальный реестр пациентов, с которыми врач уже работал
  (id, отображаемое имя, сводка, время последней активности), хранится в `localStorage` по
  `doctorId`. Пополняется при добавлении пациента на странице «Пациенты» и при открытии чата.
- Рабочий стол и календарь врача показывают активность на основе этого реестра, а не серверной
  очереди/расписания — это отражено пояснительными подсказками в UI.
- Профиль врача (специализация, номер сертификата) отображается только на чтение — в контракте
  нет эндпоинта обновления профессиональных данных врача.

### Настройка

Скопируйте `.env.example` в `.env.local` и укажите адрес API Gateway:

```bash
cp .env.example .env.local
# VITE_API_BASE_URL=https://api.vitals.example
```

Если оставить `VITE_API_BASE_URL` пустым, запросы уходят на тот же origin (`/api/v1/...`) —
удобно, если фронтенд обслуживается за реверс-прокси, который проксирует `/api` на гейтвей.

## Видео-консультации

Видео встроено в экран консультации: тот же чат, без отдельной страницы звонка.

- Пациент: запись (`ConsultationSession`) и свободный чат с врачом (`DoctorChat`).
- Врач: чат с пациентом (`PatientChat`) — видео, чат и панель диагноза / рецепта / справки.
- Старт: «Начать видео» / «Присоединиться». Завершение видео не закрывает чат. «Завершить консультацию» закрывает весь приём (видео останавливается заранее).
- DEV: нативный WebRTC P2P (`mode: p2p`), ICE из ответа `/video/start`, сигналинг SignalR
  `{VITE_API_BASE_URL}/api/v1/consultations/hub`. Режим `sfu` в UI не подключается — чат остаётся доступен.
- Камера и микрофон работают в браузере только на `https` или `localhost`.

## Запуск

```bash
npm install
npm run dev
```

## Структура

- `src/api` — типизированный клиент API Gateway (по одному модулю на тег контракта) + хранение
  токенов/роли
- `src/pages/patient` — экраны пациента (маршрут, ИИ-триаж, документы, врачи, профиль, поддержка и
  т.д.)
- `src/pages/doctor` — экраны врача (рабочий стол, календарь, пациенты, карточка пациента, чат,
  профиль, уведомления) + локальный реестр пациентов (`contacts.ts`)
- `src/pages/Auth.tsx` — общий экран входа/регистрации с выбором роли
- `src/layouts` — каркасы с сайдбаром для пациента и врача
- `src/components/ui` — базовые UI-примитивы (Button, Card, Input и т.д.)
- `src/lib/useAsyncData.ts` — хук для загрузки данных с состояниями loading/error
- `src/lib/useConsultationHub.ts` / `useConsultationVideo.ts` — SignalR хаб консультации и WebRTC P2P
- `src/theme` — провайдер темы light/dark
- `src/auth` — провайдер аутентификации (JWT, роль, привязан к `src/api/auth.ts`)
